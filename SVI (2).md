
# Логика

1. Что такое SVI на нашем хосте: это IP-интерфейс хоста **внутри конкретного VLAN** на мосту `br1` (например, `br1.330` в VLAN 330).
    
2. Зачем он нужен сейчас: пока межвлановая маршрутизация на вашем L3 (172.19.1.1) не настроена, SVI даёт хосту «ногу» прямо в ту же подсеть, где сидит ВМ — поэтому пинги/SSH идут без роутера.
    
3. Как это работает на проводах: `eno1` — транк; `vnetXX` порты — access untaged в нужный VLAN; `br1` маркирует кадры по VLAN; `br1.XXX` получает IP и общается L2 с ВМ.
    
4. Когда SVI можно убрать: когда на L3 (172.19.1.1) появятся маршруты/ACL между 172.19.1.0/28 ↔ 172.19.[2–6].0/28, и вы хотите, чтобы трафик ходил **через маршрутизатор**.
    
5. Что с безопасностью/NAT/DNS: мы уже убрали `virbr2..6`, порты 53/67 не слушают — отлично. SVI не даёт DHCP/DNS, это просто «IP хоста в VLAN».
    

# Псевдографика: где живёт SVI и как идёт трафик

                `┌───────────────────── ХОСТ: att-al18 ─────────────────────┐                 │                                                           │  uplink trunk   │     eno1 (802.1Q trunk)                                   │ from switch ────┼────────────┬───────────────────────────────────────────────┤                 │            │                                               │                 │         ┌──┴──┐  Linux bridge (L2): br1 (vlan_filtering=1)│                 │         │ br1 │-------------------------------------------│                 │         └─┬───┘        │           │            │         │                 │           │            │           │            │         │                 │     access pvid320   pvid330     pvid340      pvid350…    │                 │         (untag)       (untag)     (untag)      (untag)    │                 │           │            │           │            │         │                 │        vnet44       vnet46      vnet48       vnet50/52... │                 │           │            │           │            │         │                 │        VM1           VM2         VM3         VM4/VM5      │                 │     172.19.2.2    172.19.3.2  172.19.4.2    172.19.5/6.2  │                 │                                                           │    SVI (IP хоста в VLAN):                                                   │                 │  br1.320 = 172.19.2.14/28  ← IP хоста ВНУТРИ VLAN 320     │                 │  br1.330 = 172.19.3.14/28  ← IP хоста ВНУТРИ VLAN 330     │                 │  br1.340 = 172.19.4.14/28  … и т.д.                       │                 │                                                           │                 └───────────────────────────────────────────────────────────┘`

Идея простая: **SVI** — это «подинтерфейс» мостa `br1`, у которого есть свой IP в данном VLAN. Он видит ВМ в той же /28 без участия внешнего роутера. Поэтому пинг `172.19.X.14 ↔ 172.19.X.2` у нас шёл даже тогда, когда L3 ещё не настроен.
